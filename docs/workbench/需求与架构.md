# 产品经理工作台：第一版需求与架构

确认日期：2026-10-28。用户选择整合工作台 B、单人使用，核心流程及 Markdown 导入采用建议。
部署先按单人本机实现，不开通云资源。模型选 DeepSeek，已接入并验证，人民币费用上限待确定。

## A 与 B 的取舍

| 选项 | 收益 | 代价 |
|---|---|---|
| A：直接部署原引擎 | 改动少、可快速体验、上游更新更容易同步 | 流程与页面受原项目约束，缺少统一的开发任务和工作台数据管理 |
| B：整合个人工作台（已选） | 多产品统一入口，需求、版本、方案、任务可关联，后续前端可独立设计 | 需新增 API、数据层和测试；上游更新需要评估合并 |

## 核心闭环

输入点子 → 访谈（每轮最多五个关键问题）→ 需求草稿 → 用户确认 PRD →
方案推导 → 开发任务拆解 → 用户跟进任务 → 新需求保存新版本 → 重新推导 → 文档导出。
已有 PRD 可导入 Markdown，跳过初始访谈。所有生成均在显式接口调用后发生。

验收：重启后文档版本和任务状态保留；草稿不可自动成为正式 PRD；
需求变更使旧方案/任务过时；失败可查看进度、手动重试；导出可读到历史文档。
方案与任务质量需真实 DeepSeek 样例验收，不能用离线测试结论替代。

本轮不开发正式前端、团队账户、竞品联网研究、自动写代码、自动部署或消息发送。
先把本人跨产品管理需求的闭环做通；后续再补界面和部署方式。

## 七层落地

| 层 | 本轮实现 |
|---|---|
| 交互 | HTTP JSON API、OpenAPI 与 Swagger 验收页；后续接正式前端 |
| 产品 | 产品列表、需求访谈、草稿确认、不可变文档版本、任务状态、ZIP 导出 |
| 编排 | 串行后台任务、持久事件、失败/中断状态、人工重试；方案分阶段执行，模型步骤由官方DSH Harness运行 |
| 模型 | DSH Python SDK0.2.1rc2与原生子进程 → DeepSeek官方接口；结构校验、一次纠错、调用/token护栏 |
| 能力集成 | 复用 Blueprint 的拆解/规则选型/七层方案/审稿；新增访谈与任务结构化输出 |
| 数据 | SQLite WAL 与事务；产品、消息、文档、任务、生成记录、事件；阶段缓存留在本机 |
| 基础设施 | Python 3.12、FastAPI、Uvicorn单进程、独占锁、127.0.0.1；独立home与cwd的DSH子进程 |

请求 → 项目与版本校验 → 任务持久入队 → 模型与 Blueprint → 结构校验 →
产物、任务、消息及完成状态在一个数据库事务提交 → 读取或导出。

源文档采用 UUID 标识和递增版本，关联生成时的 PRD；开发任务另关联技术方案版本。
按用户后续澄清，Harness采用DeepSeek官方开源底座，第一阶段只做文档流程，代码执行之后再定。
具体版本、组合配置与验证见 `Harness接入.md`。
PRD 更新使用 `expected_version` 防止旧客户端覆盖；生成期间阻止修改该产品 PRD。
同一产品最多一个未完成生成任务，整个进程最多一个模型任务执行。
状态库仅一个服务进程独占，重启将 queued/running 标为 interrupted，绝不自动重新花费模型用量。

安全边界：本机访问；API 不读写密钥；密钥仅存本机 `.env`；不回显供应商异常；
文件名不作为路径；SQL 使用参数；文档内容视为数据，不授予执行工具权限。
手动任务状态与自动生成分离，没有授权外部发送、云资源购买或代码执行的工具。
