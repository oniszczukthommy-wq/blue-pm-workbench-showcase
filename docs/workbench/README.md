# Blue产品经理工作台 · 本机版

这是你的单人本机产品工作台。默认首页是产品助理聊天，工作台页保留产品拆解、想法验收、后端整合、
前端整合、开发上线五个入口，侧栏保留产品助理、工作台、全部产品、文档库、任务中心和产品快捷入口。
产品页现已加入「产品拆解」：七路公开联网搜证、证据覆盖与彩色 HTML 报告，见 [产品拆解接入](产品拆解接入.md)。
运行层已接入 DeepSeek 官方开源 Harness，固定 SDK 与运行时版本 `0.2.1rc2`。
本轮只运行文档流程，不开放编程/命令工具。具体接法见 `Harness接入.md`。

## 打开与停止

首次使用先按下方「技术安装与验证」完成依赖、前端构建和桌面入口安装。
之后双击桌面的 **Blue产品经理工作台.app**，后台服务会按需启动并自动打开浏览器。
重复双击只打开工作台，不会中断任务或重复启动服务，也不会自动调用模型。
项目根目录的 `启动工作台后端.command` 是兼容入口，作用相同。

- 工作台首页：http://127.0.0.1:8788/
- 接口文档（开发调试）：http://127.0.0.1:8788/docs
- 健康状态：http://127.0.0.1:8788/api/health

关闭网页后后台继续运行；需要停止时，双击项目根目录的 `停止工作台.command`。
有 AI 任务进行中时会拒绝停止，等任务完成后再试。数据留在 `data/`，下次启动会恢复。
只监听本机，不提供公网访问。没有设置开机自启，重启电脑后双击桌面图标即可。

桌面应用是启动入口，运行文件和数据仍在安装时的项目目录，请保留此目录；移动项目后需更新本机启动配置。
本机启动配置在 `~/Library/Application Support/Blue产品经理工作台/`；
日志在 `~/Library/Logs/Blue产品经理工作台/`。密钥仍只从项目 `.env` 读取，不写入桌面应用或启动配置。
本机安装过程、运行日志与重启验证记录不上传 GitHub。

## 配置 DeepSeek

把根目录的 `.env.workbench.example` 复制为 `.env`，在 `ANTHROPIC_API_KEY=` 后填写自己的 Key 并保存。
`MODEL_ID` 默认 `deepseek-flash`。不用把 Key 发到聊天中，也不用在接口页面填写。
每个新任务会重新读取配置，无需重启服务。运行中的任务保持启动时的配置。

接口固定使用 DeepSeek 官方 Anthropic 兼容地址，未接入任意模型中转。
来源：https://api-docs.deepseek.com/guides/anthropic_api/
Key 不会通过 API 返回；项目数据与生成上下文会发送给 DeepSeek，进行模型推理。

当前已经接入 DeepSeek 并完成真实技术验收，研究样例与模型运行记录只保存在本机，不随源码上传。
技术链路可用不代表生成内容已通过业务验收，PRD 仍由使用者确认。

没有 Key 时可以创建产品、导入和修订 PRD、导出文档。访谈、方案和任务生成会返回
`MODEL_NOT_CONFIGURED`，不会排入后台，更不会返回假生成结果。

每个生成任务默认限制 16 次模型响应、200000 个累计 token，单次输出上限 16384 token，
单次总等待上限 180 秒。Harness 的自动网络重试和压缩关闭；结构化格式错误最多纠正一次。
这些是调用与 token 护栏，可能在最后一次返回后超过阈值，**不是人民币硬预算**。
重试会产生新的模型用量。默认同一时间只执行一个任务。

## 在工作台里使用

产品助理可直接讨论用户、产品价值、需求取舍与优先级，不要求先新建产品。
新对话可选择关联一个已有产品，助理只读取该产品的资料；需要切换产品时新建对话，避免不同产品混用。
回复的引用标签显示实际资料和版本，点击可读取对应原文。旧版方案和任务会标为旧资料，长文节选会明确提示。

点击回复下的「保存讨论结论」，即可进入原文档库；自由讨论的结论可暂不关联产品。
需要汇总整段讨论时，先请助理总结再保存该条回复。结论保存不会再次请求模型，也不会成为正式 PRD。
助理提出的流程动作会显示确认按钮，可从对话中发起拆解、整理需求草稿、方案或任务生成。
原有 PRD/方案前置与版本检查继续有效，正式 PRD 仍由本人确认。对话失败保留消息，手动重新回复才再次调用模型。

原五阶段流程继续使用：

1. 点右上角「新建产品」，填写名称和一句话想法。
2. 进入「需求访谈」，发送想法并回答 AI 的问题；已有 PRD 可直接导入 Markdown。
3. 展开需求草稿审阅，点「确认成为 PRD」；如需修改，点「编辑后再确认」。
4. 在「技术方案」生成方案，再到「开发任务」拆解任务，用看板或列表维护状态。
5. 新需求在 PRD 编辑器保存为新版本，旧方案会提示需要更新；历史可在「版本与记录」回看。
6. 产品页侧栏「导出资料」可下载全部文档版本与任务状态。

产品、文档、草稿、任务与版本记录均来自本机真实数据。
生成期间可以切换页面；失败或中断会保留记录，并提供手动重试入口。

## 接口方式验收（开发调试）

在 `/docs` 展开接口，点 `Try it out`，填写 JSON，点 `Execute`。

1. `POST /api/projects`：填 `name`、`idea`，复制返回的 `id`，后续作为 `project_id`。
2. 需求路径二选一：
   - 访谈：`POST /api/projects/{project_id}/interview`，填 `message`。返回生成任务 `id`。
     用 `GET /api/jobs/{job_id}` 查询，直到状态为 `done`。根据 `result.document_id` 读取草稿，
     查看 `metadata.reply/questions/ready`。需要回答就继续访谈。
     确认满意后调用 `/prd/confirm`，填 `draft_id` 和 `expected_version`。
   - 导入：`POST /api/projects/{project_id}/prd/import`，填 `filename: "需求.md"`、
     `content`（文件全文）与 `expected_version: 0`。
3. `POST /api/projects/{project_id}/plan`：开始方案推导，查询任务进度和产物。
4. `POST /api/projects/{project_id}/tasks/generate`：按当前 PRD 和方案拆解开发任务。
5. `GET /api/projects/{project_id}/tasks`：查看任务；用 PATCH 接口把状态设为
   `todo`、`doing`、`done`、`blocked`。
6. 新需求：重新访谈并确认草稿，或 `POST /prd` 保存修订全文。`expected_version`
   必须为当前 PRD 版本（初始为 0，已有 V1 时填 1）。`change_note` 写本轮改动。
   历史内容不会覆盖，新 PRD 会把旧方案和任务标为 `stale`。
7. `GET /api/projects/{project_id}/export`：下载 ZIP，包含文档全部版本、项目摘要和任务状态。

Markdown 导入只接收 UTF-8 纯文本和 `.md` 文件名，正文最多 100000 个字符，请求最多
450000 字节。文件名不参与磁盘写入。当前不支持 Word/PDF、附件、外部工具连接。
单次访谈消息最多 12000 字符；历史累计超过 80000 字符时，需要先落成 PRD。

## 生成记录与中断恢复

- `/api/projects/{project_id}/jobs`：查看调用次数和输入/输出 token 汇总，失败任务用量也计入。
- `/api/jobs/{job_id}/events?after=0`：轮询进度，后续填最后一个 `seq`；每页最多 200 条。
- 状态：`queued → running → done/failed`；服务重启后的未完成任务变成 `interrupted`。
- 失败或中断时，`POST /api/jobs/{job_id}/retry` 手动重试。不会自动恢复调用、自动扣用量。
- 方案重试复用已完成阶段缓存；PRD 已变更时拒绝旧方案重试，需要重新生成。
- PRD 更新后，旧访谈不能重试、旧草稿不能直接确认；方案更新后，旧任务拆解不能重试。
- 停止服务会取消排队任务、停止后续模型调用，记录为 `interrupted`；已经发出的请求
  可能仍需等待返回，已发生的模型用量不能撤销。
- 任务状态的 `done` 表示你标记完成，不代表工作台替你执行或验证了开发任务。

## 数据与备份

`data/workbench.sqlite3` 保存产品、对话、文档、版本、任务和生成记录。
`data/runs/` 保存引擎阶段缓存，便于重试。
会话、消息、引用快照、讨论结论及动作记录也保存在同一 SQLite 中；关联产品的结论包含在该产品 ZIP 导出内。
数据目录不提交到 Git。完整备份时先停止服务，再复制整个 `data/` 目录。
ZIP 导出是产品资料交付包，不是可恢复数据库的完整备份。

只供本机单人使用，未实现账号登录。服务检查 Host 与 Origin，并限制跨站请求和正文大小。
所有接口错误统一为 `{"error":{"code":"...","message":"..."}}`。
业务错误使用 404/409，输入错误 422，大请求 413，非法来源 403。
不返回异常堆栈、密钥或供应商原始报错，不提供删除接口和自动代码执行接口。

## 技术安装与验证

要求 Python 3.12、Node.js 22.13+ 与 pnpm；以下在项目根目录执行。
先安装依赖和构建前端，复制配置并填写自己的模型 Key。没有 Key 也能运行文档与产品管理。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-workbench.lock.txt
cp .env.workbench.example .env
pnpm --dir workbench-ui install --frozen-lockfile
pnpm --dir workbench-ui run build
.venv/bin/python -m backend
```

上面的手动启动方式需要保持终端打开，按 Ctrl+C 停止。macOS 可在完成构建后安装桌面启动器：

```sh
.venv/bin/python scripts/install_desktop_workbench.py
```

桌面入口由安装程序在当前电脑生成，不把 `.app`、运行环境或后台服务配置提交 Git。

自动测试：

```sh
.venv/bin/python -m pytest -q tests/workbench tests/test_web_ui.py tests/test_workspace_loop.py tests/test_blueprint_engine.py tests/test_llm_robustness.py
.venv/bin/python scripts/verify_workbench.py
```

测试中的离线模型仅注入测试进程；运行服务没有 mock 开关，也不在 Harness 失败时静默回退。
实际进程重启验证脚本会在临时目录启动子进程、写入文档、停止并重启，再检查原文和版本。
真实模型技术验收的产物、用量和会话记录保留在本机；仓库只包含源码、方法论与离线测试。


## 产品方法、资料引用与修改审阅（2026-10-29）

- 聊天输入框上方的「自由讨论」菜单可切换问题定义、优先级与范围、PRD 审查；按当前选择生效，未选择时保持自由讨论。
- 关联产品后点击「引用资料」，选择具体文档版本；可以引用全文，或选中原文后点「引用选中段落」。每条消息最多四份资料，选段最多 6000 字，较长全文会明确按节选处理。
- AI 可对完整读取且当前有效的 PRD、草稿、技术方案提出修改建议。点击「查看差异」，可看差异、修改后全文或原文；确认后保存新版本，拒绝则保留原文。原文或 PRD 发生变化时旧建议不可覆盖新版本。
- 任务表与结构化拆解报告通过原有生成流程更新，避免破坏任务状态或报告证据。自动写代码与上线执行仍未接入。
- 搜索入口与 ⌘/Ctrl K 支持文档正文、历史对话、结论、产品与任务。点击对话结果定位原消息；超过 60 条时请缩小关键词范围。
- 产品与对话的「•••」菜单、文档阅读窗的「移入回收站」提供删除入口；均需确认，未提供不可恢复的永久清空操作。
- 左下方「回收站」恢复原记录。产品移入回收站时其资料和关联对话一起隐藏；恢复产品不会复活此前单独移除的文档。
- 有 AI 生成进行中时阻止移除。被其他文档或任务依赖的文档需保留，或整体移除产品。当前文档被移除时不把旧版自动提升为当前版本；恢复或新建时版本号不重用。

三个技能来源于 Simin Lab，完整文件与哈希登记在 `.agents/skill-installations.json`，运行集成位于 `backend/workspace.py` 和 `backend/assistant.py`；版权声明在 `licenses/Simin-Lab-MIT.txt`。
